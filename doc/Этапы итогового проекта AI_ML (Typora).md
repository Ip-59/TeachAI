# Этап №1 | AI/ML | Утверждение темы итогового проекта

Описание занятия

**Укажите тему итогового проекта и дайте небольшой комментарий:**

- Предпосылки (почему выбрали именно эту тему?)
- Описание задачи.
- Как видите ее решение
- Какую базу планируете использовать

**Источники для выбора темы:**

\- Стажировка (рабочий проект от заказчика, но со своими наработками). 

- Если стажировка еще идет, то необходимо уведомить Тимлида. Работайте над проектом для фиксации результата Тимлидом. Должна быть активность на стажировке: отчеты, польза проекту.
- Если стажировка уже завершилась, то обязательное условие для использования темы со стажировки - присутствие на итоговом лендинге с результатами работы по проекту;
- Использование только открытых данных для дипломного проекта: категорически нельзя использовать датасет со стажировки; 
- Использование только своих наработок: не используйте приложения созданные на стажировке кем-то еще (алгоритмы и идеи брать можно). Должна быть представлена серия экспериментов с итеративным улучшением качества.
   

\- Свой проект (или рабочий проект под заказ). 
Если у вас уже имеется тема, необходимо согласовать её с куратором. Обращаем внимание на то, что написание итогового проекта - это процесс с фиксацией экспериментов и логики при создании проекта, а не просто предоставление готового решения.

\- Список тем для дипломного проекта. Тему можно выбрать из списка готовых (список приложен ссылкой в материалах) или аналогичную.
https://drive.google.com/file/d/1TffkKvP-iRbIjvSj9D_EjI2zjUAHaOVY/view?usp=sharing 

\- Индивидуальное решение для исследований. 
Выбрать область, которая вам наиболее интересна (например: медицина, беспилотные автомобили,  распознавание изображений и т. д.), найти проблемы, которые имеются в этой области, обсудить с  куратором, возможно ли решить эту проблему с помощью нейросетей.

# Этап №2. | AI/ML | Сбор базы

Описание занятия

**— Сбор базы не требуется.**
Для некоторых проектов сбор базы не требуется, например для задач обучения с подкреплением
(обучение бота карточным играм или игре Сапёр), где база собирается во время обучения.

**— База есть в наличии (возможно потребуется дополнить)**
Взять готовую базу у куратора. Для повышения точности предсказания нейросети может
потребоваться дополнить примерами.

# Этап №5. | AI/ML | Создание финальной версии НС

Описание занятия

**Задание сдается в виде ссылки на папку с ноутбуками и доп. файлами для корректной работы ноутбуков (если потребуется), а так же word-документом из Этапа No4.**
*Примечание: слово функция – это пере используемый блок кода, так же как и классы и модули. Потому использование слова «Функция» далее так же может относиться как к классу, так и к модулю.*
 

**Первый ноутбук финальный (используем/тестируем готовую модель) должен соответствовать следующим критериям:**

1.  Friendly user interface – означает, что незнающему человеку достаточно определить все функции(классы) и в конце запустить «тестовую ячейку», в которой ему можно ввести свои тестовые данные (input, google.colab.files.upload) для проверки, провести всю предобработку, предсказать, сделать постобработку данных и сделать понятный ему вывод из предсказания
2. Весь код должен быть разбит на отдельные части («функции») и иметь одну главную «функцию» запуска остальных для проверки работы модели, которая запускается в последней ячейке 
   **– Примеры:**
   a. Мы должны загрузить файл – должна быть функция загрузки файла, что принимает путь до
   файла.
   b. Должна быть очистка данных – отдельная функция, что принимает сырые данные
   c. Должна быть предобработка данных – отдельная функция, что принимает как минимум чистые
   данные
   d. Должно быть создание «загрузчика» (loader) - отдельная функция, что принимает пред
   обработанные данные
   e. Получение/создание модели – отдельная функция, что принимает пути до загрузки и флаги
   (preload->boolean)
   f. Обучение модели – отдельная функция, что принимает флаги пред загруженности модели и
   «загрузчики»
   g. Вывод графиков – отдельная функция, что принимает history обучения
   h. И так далее.
3. Если для корректной работы ноутбука(предсказания) требуются файлы подгрузки (модель, веса, тестовые данные), то они должны лежать в одной локации вместе с этим ноутбуком.
4. Во всех «функций», что загружают/сохраняют файлы – пути должны быть параметрами с значением по умолчанием (чтобы функцию можно было запустить без явного указания пути)
5. Каждая «функция» должна быть чистой – она должна использовать внутри себя только те
   переменные, которые были ей переданы как параметры. Исключение – это использование других
   «функций» как создание новых данных внутри себя. Но без использования результатов предыдущих
   функций внутри себя, если эти результаты были получены за пределами текущей функции

**Второй ноутбук (здесь Вы показываете свои эксперименты при создании модели) должен соответствовать следующим критериям:**

1. Выводы в ячейках должны быть воспроизводимыми при повторном запуске (небольшие неточности в модели из-за разных весов инициализации не критично)
2. Если в ноутбуке используются загружаемые данные – они должны лежать рядом(или как минимум их sample(часть)) в локации ноутбука.
3. Весь код должен быть разбит на отдельные части («функции»), чтоб исключить повторений в коде. Комментарии к отдельным частям кода.
4. Все эксперименты должны быть видны т.е не используйте одну ячейку, как поле для экспериментов, а дублируйте их, чтобы проследить некие закономерности, но без «фанатизма» (пример – изменили с 24 нейронов на 25)
5. Графики должны быть видны на разные эксперименты. Если ваша модель генерирует нормализованные данные, то для графиков с временными рядами нужно делать обратную трансформацию. 
6. В конце должен быть вывод по всем архитектурам, параметрам, их точностям. Также должна быть выбрана «лучшая» модель в соотношении точность/кол-во параметров.
7. Выводы о том, удалось ли добиться желаемой точности. Если не получилось, то написать обоснование, почему не получилось и какие есть еще способы решения этой проблемы.
