Скорректированное техническое задание (ТЗ) на разработку TeachAI
================================================================

1. Назначение системы

-

---

TeachAI — это интеллектуальная обучающая система, предназначенная для интерактивного индивидуального обучения студентов. Она должна:

*

 Обеспечивать персонализированное обучение на основе профиля студента с учетом выбранного курса, общего времени обучения и длительности занятий.

*

 Генерировать учебный план и контент уроков через OpenAI API.

*

 Поддерживать работу в графическом интерфейсе Jupyter Notebook с использованием интерактивных элементов.

*

 Сохранять профиль студента, его прогресс и данные в формате JSON.

*

 Диагностировать и логировать все взаимодействия, включая ошибки и некорректные действия.
2. Функциональные требования

-

---

#

# 2.1. Начальное взаимодействие с пользователем

*

 При первом запуске система должна:
  1. Проверить наличие файла `.env` и параметра `OPENAI_API_KEY`. Если файл отсутствует или ключ не задан, выдавать ошибку с инструкцией, как это исправить.
  2. Спросить у пользователя:
- Имя.
- Общую продолжительность обучения (в часах).
- Длительность одного занятия (в минутах).
- Формат общения (формальный, дружеский, непринужденный, краткий).
  3. Загрузить список доступных курсов из файла `courses.json`.
  4. Предложить выбрать курс из списка и отобразить его описание.
  5. Сохранить введенные данные в `state.json`.

#

## 2.2. Генерация учебного плана

*

 После выбора курса и заполнения профиля система должна:
  1. Сформировать запрос к OpenAI API для генерации персонализированного учебного плана.
  2. Учебный план должен учитывать:
- Выбранный курс (название, описание).
- Общее время обучения.
- Длительность одного занятия.
  3. Учебный план должен иметь иерархическую структуру:
- Разделы (sections).
- Темы (topics) внутри разделов.
- Уроки (lessons) внутри тем.
  4. Для каждого элемента плана (раздел, тема, урок) должны быть указаны:
- Уникальный идентификатор.
- Название.
- Краткое описание.
- Необходимое время изучения (в минутах).
  5. Сохранить сгенерированный план в `state.json`.

#

## 2.3. Обучение и прохождение курса

*

 Система должна:
- Отображать текущий урок согласно учебному плану.
- Генерировать содержание урока через OpenAI API при переходе к нему, учитывая:
- Название и описание урока из плана.
- Желаемую длительность изучения (указанную в профиле).
- Выбранный стиль общения.
- Объем урока должен соответствовать указанной длительности занятия.
- Поддерживать линейное прохождение курсов, но предусмотреть возможность возврата к предыдущим урокам.
- Отображать уроки с использованием интерактивных элементов Jupyter Notebook (`ipywidgets`).
- Предоставлять интерактивные функции на странице урока:
- "Объясни подробнее" - получение расширенного объяснения через API.
- "Задать вопрос" - возможность задать вопрос по материалу и получить ответ через API.
- "Приведи примеры" - получение практических примеров по материалу урока через API.

#

## 2.4. Контроль знаний

*

 После каждого урока система должна:
  1. Предлагать пройти тест по материалу урока.
  2. Генерировать 5 вопросов с выбором из 3 вариантов ответа через OpenAI API.
  3. Для правильного ответа:
- Подсвечивать его зеленым цветом.
  4. Для неправильного ответа:
- Подсвечивать его красным цветом.
- Показывать правильный ответ.
  5. Сохранять результаты тестов в `assessment_log.json`.
  6. Пересчитывать и отображать средний балл за курс.
  7. Рассчитывать общий прогресс прохождения курса с учетом пройденных уроков и результатов тестов.

#

## 2.5. Логирование

*

 Логи хранятся в следующих файлах:
- `lesson_history.md` — история уроков.
- `questions_log.json` — вопросы пользователя и ответы системы.
- `assessment_log.json` — результаты тестов.
- `activity_log.json` — общее логирование действий.
- `teachai.log` — технические логи системы.

*

 Логи должны включать:
- Время действия.
- Тип действия (успешное или с ошибкой).
- Подробности ошибки (если есть).
- Содержание запросов и ответов API (в сокращенном виде).

#

## 2.6. Диагностика и отладка

*

 Все модули системы должны включать отладочные сообщения.

*

 При возникновении ошибок:
- Указывать причину и возможные пути решения.
- Предлагать альтернативные действия.

*

 Система должна иметь возможность работать в демо-режиме при отсутствии API ключа.

#

## 2.7. Интерактивный интерфейс

*

 Использовать `ipywidgets` для:

- Ввода текстовых данных.
- Выбора из списка (например, курса или формата общения).
- Кнопок для управления действиями (например, переход к следующему уроку).
- Отображения прогресса обучения.

*

 Интерфейс урока должен включать:

- Заголовок урока.
- Содержание урока.
- Оценку времени изучения.
- Кнопки навигации ("Назад", "Далее").
- Интерактивные функции ("Объясни подробнее", "Задать вопрос", "Приведи примеры").
- Кнопку перехода к тесту.
3. Технические требования

-

---

#

## 3.1. Архитектура

*

 Модульная структура:
- `engine.py` — основной модуль.
- `state_manager.py` — управление состоянием.
- `content_generator.py` — генерация контента через API.
- `assessment.py` — контроль знаний.
- `logger.py` — логирование.
- `interface.py` — интерактивный интерфейс.
- `config.py` — работа с `.env`.
- `demo_content.py` — демонстрационный контент для автономной работы.
- `courses.json` — список доступных курсов.

#

## 3.2. Хранение данных

*

 Основной файл состояния: `state.json`.

*

 Структура учебного плана и прогресса обучения.

*

 Формат: JSON с поддержкой вложенных структур.

#

## 3.3. Взаимодействие с OpenAI API

*

 Реализовать следующие типы запросов:
  1. Генерация учебного плана на основе данных о курсе и времени обучения.
  2. Генерация содержания урока с учетом длительности занятия и стиля общения.
  3. Генерация дополнительных объяснений по материалу урока.
  4. Генерация практических примеров.
  5. Ответы на вопросы пользователя.
  6. Генерация тестовых вопросов и ответов.

*

 Кэширование результатов запросов для экономии API вызовов.

*

 Корректная обработка ошибок API.

#

## 3.4. Используемые библиотеки

*

 Python 3.8+.

*

 `openai` для работы с OpenAI API.

*

 `ipywidgets` для графического интерфейса.

*

 `python-dotenv` для работы с `.env`.

*

 `json` для работы с JSON данными.

*

 `logging` для системного логирования.

#

## 3.5. Обработка ошибок

*

 Некорректный ввод пользователя должен:

- Поясняться пользователю.
- Предлагаться повторный ввод.

*

 Ошибки API:

- Сообщать пользователю о проблеме (например, превышение лимита запросов).
- Предлагать использование демо-контента при недоступности API.
- Предлагать повторить запрос позже.
4. План разработки

-

---

1. **Базовая структура**:

- Создание файлов модулей с базовой функциональностью.
- Подготовка файла `courses.json` с описанием доступных курсов.

2. **Профиль и выбор курса**:

- Реализация интерфейса профиля пользователя.
- Реализация загрузки и отображения списка курсов.

3. **Генерация учебного плана**:

- Реализация запроса к OpenAI для создания персонализированного учебного плана.
- Сохранение плана в state.json.

4. **Отображение уроков**:

- Генерация содержания урока через API.
- Реализация интерфейса урока с интерактивными функциями.

5. **Интерактивные функции**:

- Реализация функций "Объясни подробнее", "Задать вопрос", "Приведи примеры".
- Тестирование и оптимизация взаимодействия с API.

6. **Контроль знаний**:

- Генерация тестов через API.
- Проверка ответов и отображение результатов.

7. **Логирование и диагностика**:

- Реализация комплексного логирования.
- Добавление отладочных функций.

8. **Демо-режим**:

- Создание модуля `demo_content.py` для работы без API.
- Тестирование режима автономной работы.

9. **Финальное тестирование**:

- Проверка всех функций системы.
- Устранение выявленных ошибок.
- Оптимизация производительности.

10. Требования к демонстрационному режиму

-

---

Для возможности тестирования и демонстрации системы без доступа к API, необходимо:

1. Создать файл `demo_content.py`, содержащий:

- Примеры минимальных учебных планов для разных курсов. 2 Очень кратких плана с минимальным содержанием. Только для демонстрации.
- Примеры содержания уроков. 2 Очень кратких урока с минимальным содержанием. Только для демонстрации.
- Примеры ответов на возможные вопросы. 2 Очень кратких ответа с минимальным содержанием. Только для демонстрации.
- Примеры подробных объяснений. 2 Очень кратких объяснения с минимальным содержанием. Только для демонстрации.
- Примеры практических примеров. 2 Очень кратких примера с минимальным содержанием. Только для демонстрации.
- Примеры тестовых вопросов. минимальное количество максимально коротких вопросов. Только для демонстрации.

2. Система должна автоматически определять наличие API ключа и при его отсутствии переключаться в демо-режим.

3. Пользователь должен быть уведомлен, что система работает в демо-режиме с ограниченной функциональностью.

4. Должна быть возможность переключения между демо-режимом и режимом с реальным API через настройки конфигурации.

5. Критерии приемки

-

---

Система считается принятой, если:

1. Все базовые функции работают корректно в режиме с API и в демо-режиме.
2. Учебный план генерируется с учетом указанного общего времени обучения и длительности занятий.
3. Содержание уроков соответствует выбранному стилю общения и оптимально по объему для указанной длительности занятия.
4. Интерактивные функции (объяснения, вопросы, примеры) работают корректно.
5. Тесты генерируются и проверяются правильно.
6. Прогресс корректно сохраняется и загружается при повторном запуске.
7. Система корректно обрабатывает все возможные ошибки.
8. Интерфейс дружелюбен и понятен пользователю.
