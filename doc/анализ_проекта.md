# TeachAI — Полный анализ проекта

## Обзор проекта

TeachAI — образовательная платформа на базе Jupyter Notebook, которая генерирует персонализированные курсы по программированию на Python с помощью LLM API (OpenAI / Azure / OpenRouter). Основные возможности:
- Динамическое создание плана курса, генерация уроков, тестирование, вопросы-ответы, интерактивные ячейки кода
- Интерфейс на `ipywidgets` внутри Jupyter
- Хранение состояния в JSON, логирование действий и результатов тестов

Кодовая база: **~40 Python-файлов**, ~15 000 строк кода.

## 🔴 Критические проблемы

### 1. Две параллельные, несовместимые системы вызова LLM

> [!CAUTION]
> В проекте существуют **две полностью независимые** системы для обращения к LLM API — с разными моделями, разной настройкой прокси и разной обработкой ошибок.

| Аспект | `LLMGenerator` ([llm.py](file:///media/ip-59/64GB/TeachAI/llm.py)) | `BaseContentGenerator` ([content_utils.py](file:///media/ip-59/64GB/TeachAI/content_utils.py)) |
|---|---|---|
| **Модель** | `os.getenv("LLM_MODEL", "gpt-4")` | Жёстко прописана `gpt-3.5-turbo-16k` |
| **Прокси** | Читает 5 переменных окружения, создаёт `httpx.Client` с `HTTPTransport` | Читает 3 переменных, создаёт свой `httpx.Client` |
| **Используется** | `ContentGenerator` (фасад), `CoursePlanGenerator` (косвенно) | Все `*Generator` классы: `LessonGenerator`, `QAGenerator`, `AssessmentGenerator`, `ExplanationGenerator`, `ExamplesGenerator`, `ConceptsGenerator`, `ControlTasksGenerator`, `RelevanceChecker` |
| **Обработка ошибок** | `_safe_chat` с определением региональных ограничений | Общий `try/except` |

**Последствия**: Если пользователь устанавливает `LLM_MODEL=gpt-4o` через переменную окружения, план курса будет генерироваться через эту модель, а весь остальной контент (уроки, тесты, объяснения, примеры) — тихо использует `gpt-3.5-turbo-16k`. Настройки прокси тоже могут различаться. Это почти наверняка баг, а не намеренное решение.

**Рекомендация**: Убрать `BaseContentGenerator.make_api_request` и сделать так, чтобы все генераторы использовали единственный экземпляр `LLMGenerator`.

### 2. `exec()` без песочницы

> [!CAUTION]
> Пользовательский код выполняется через `exec()` **без какой-либо изоляции** в нескольких файлах.

- [control_tasks_generator.py](file:///media/ip-59/64GB/TeachAI/control_tasks_generator.py) — `validate_task_execution()` (строка 543), `_parse_control_task_response()` (строка 342)
- [interactive_cell_logic.py](file:///media/ip-59/64GB/TeachAI/interactive_cell_logic.py)
- [control_tasks_interface.py](file:///media/ip-59/64GB/TeachAI/control_tasks_interface.py)

В `_parse_control_task_response` код `solution_code`, сгенерированный LLM, выполняется для проверки — то есть **выход нейросети напрямую попадает в `exec()`**. При этом `eval()` использует `{"__builtins__": {}}`, а `exec()` — нет, что даёт полный доступ к `os`, `subprocess` и т.д.

**Рекомендация**: Как минимум передавать `{"__builtins__": {}}` в `exec()`, а лучше использовать `RestrictedPython` или `subprocess` с ограничениями ресурсов.

### 3. Три почти идентичных форматтера контента

> [!WARNING]
> В проекте три **копии** по сути одного и того же Markdown→HTML конвертера:

| Файл | Класс | Строк |
|---|---|---|
| [content_formatter.py](file:///media/ip-59/64GB/TeachAI/content_formatter.py) | `ContentFormatter` | 373 |
| [content_formatter_v2.py](file:///media/ip-59/64GB/TeachAI/content_formatter_v2.py) | `ContentFormatterV2` | 375 |
| [content_formatter_final.py](file:///media/ip-59/64GB/TeachAI/content_formatter_final.py) | `ContentFormatterFinal` | 488 |

`ContentFormatter` и `ContentFormatterV2` совпадают побайтово (одинаковый CSS, одинаковая логика). `ContentFormatterFinal` отличается:
- `font-weight: 900 !important` буквально на каждом элементе (заголовки, параграфы, списки, код, *даже курсив*)
- Чёрно-белая тема с инвертированными блоками кода
- `text-shadow` на всём

Все три дублируют один и тот же парсинг Markdown (заголовки, жирный, курсив, списки, блоки кода) с незначительными вариациями исправлений багов.

**Рекомендация**: Оставить только `ContentFormatterFinal`, удалить два других. А ещё лучше — заменить самописный парсер Markdown на библиотеку `markdown` + `Pygments` для подсветки синтаксиса.

## 🟡 Значимые проблемы

### 4. Массовое дублирование CSS

CSS-стили определены как Python-строки минимум в **7 разных файлах**:

| Файл | Область CSS |
|---|---|
| `content_formatter.py` | Контент урока (148 строк) |
| `content_formatter_v2.py` | То же самое (148 строк, идентичная копия) |
| `content_formatter_final.py` | То же самое (211 строк, высококонтрастный вариант) |
| `content_utils.py` | `BASE_CSS_STYLES`, `EXAMPLES_CSS_STYLES`, `EXPLANATION_CSS_STYLES` |
| `qa_generator.py` | Стили ответов на вопросы |
| `relevance_checker.py` | Стили для нерелевантных вопросов |
| `assessment.py` | Стили тестов/квизов |
| `startup_dashboard.py` | Стили дашборда (inline) |

**Итого**: 800+ строк продублированного CSS, встроенного в Python-строки. Любое изменение стиля требует поиска и правки в нескольких файлах.

**Рекомендация**: Вынести все CSS в единый модуль `styles.py` или, ещё лучше, в `.css`-файл, загружаемый при запуске.

### 5. Отладочные `print()` в продакшен-коде

> [!WARNING]
> Код пестрит `print()`-выводом для отладки, который попадает в stdout Jupyter-ноутбука.

Примеры из [control_tasks_generator.py](file:///media/ip-59/64GB/TeachAI/control_tasks_generator.py):
```python
print("\n" + "="*80)
print("🔍 [DIAGNOSTIC] generate_control_task ВЫЗВАН")
print(f"Длина промпта: {len(prompt)} символов")
print(f"Первые 500 символов: {prompt[:500]}...")
```

Аналогичные строки есть в `assessment_generator.py`, `course_plan_generator.py`, `lesson_generator.py`, `examples_generator.py`, `concepts_generator.py` и других.

**Последствия**: Засоряют вывод ноутбука отладочным шумом и могут раскрыть содержимое промптов и ответов API конечному пользователю.

**Рекомендация**: Заменить все отладочные `print()` на `logging.debug()`. Их можно будет включить через уровень логирования при необходимости, не затрагивая пользователей.

### 6. Баг в регулярке `_remove_greetings`

В [qa_generator.py](file:///media/ip-59/64GB/TeachAI/qa_generator.py) метод `_remove_greetings` использует широкую регулярку для удаления приветствий из ответов LLM. Паттерны вроде:

```python
r"^(Привет|Здравствуйте|Добрый день|...)[\s\S]*?[.!?\n]"
```

`[\s\S]*?` может захватить несколько предложений. Если LLM начнёт с «Здравствуйте, сегодня мы рассмотрим...», удалится всё первое предложение вместе с полезным содержанием.

**Рекомендация**: Заменить `[\s\S]*?` на `[^.!?\n]*?`, чтобы матч ограничивался только предложением с приветствием.

---

### 7. `_clean_content` уничтожает существующий HTML

Во всех трёх форматтерах `_clean_content` безусловно удаляет `<div>` и `<p>` теги:

```python
content = re.sub(r'<div[^>]*>|</div>', '', content)
content = re.sub(r'<p[^>]*>|</p>', '', content)
```

Если LLM возвращает валидный HTML (что иногда случается), структура разрушается до того, как парсер Markdown создаст новые (возможно, неправильные) теги.

Кроме того, `ContentFormatter._clean_content` удаляет идентификаторы языка из блоков кода:
```python
content = re.sub(r'```\w*\n?', '```', content)
```
Это удаляет подсказку `python`, хотя все блоки и так по умолчанию считаются Python — но теряется оригинальный сигнал.

### 8. Избыточные CSS-стили в `ContentFormatterFinal`

Тема «высокого контраста» в [content_formatter_final.py](file:///media/ip-59/64GB/TeachAI/content_formatter_final.py) применяет экстремальную стилизацию:

```css
.lesson-content * { color: #000000 !important; }
.lesson-content, .lesson-content * {
    text-shadow: 0 0 1px rgba(0,0,0,0.5) !important;
}
```

- `font-weight: 900 !important` на **всём**, включая курсив и параграфы — весь текст выглядит одинаково
- Селекторы с `*` и `!important` делают невозможным переопределение стилей для конкретных элементов
- `text-shadow` на всех элементах добавляет визуальный шум

## 🔵 Качество кода и архитектура

### 9. Самописный парсер Markdown

Все три форматтера реализуют базовый конвертер Markdown→HTML с помощью регулярных выражений:
- `# заголовок` → `<h1>`
- `**жирный**` → `<strong>`
- `*курсив*` → `<em>`
- `- элемент` → `<ul><li>`

Известные проблемы этого подхода:
- Обработка `__жирный__` как `<strong>` конфликтует с именами плейсхолдеров (`__CODE_BLOCK_0__`)
- Регулярка курсива `*текст*` может конфликтовать с регуляркой жирного `**текст**` (жадное сопоставление)
- Нет поддержки вложенных списков, нумерованных списков, таблиц, ссылок или изображений
- В `ContentFormatterV2` добавлен обходной путь для коллизии с плейсхолдерами, но он хрупкий

**Рекомендация**: Использовать `import markdown` (устанавливается через pip). Библиотека обрабатывает все крайние случаи и поддерживает расширения для подсветки кода.

### 10. `BaseContentGenerator` создаёт новый клиент для каждого генератора

Каждый класс `*Generator` наследуется от `BaseContentGenerator` и вызывает `super().__init__(api_key)`, который создаёт:
- Новый `httpx.Client` с настройкой прокси
- Новый экземпляр клиента `OpenAI`

Если система создаёт ~8 экземпляров генераторов (урок, QA, тест, объяснение, примеры, концепции, контрольные задания, проверка релевантности), создаётся **8 отдельных HTTP-клиентов** и **8 отдельных экземпляров OpenAI SDK**. Это расходует соединения, память и делает настройку прокси непоследовательной.

**Рекомендация**: Использовать общий синглтон `LLMGenerator` и внедрять его в генераторы через конструктор.

### 11. Система логирования

Класс `Logger` в [logger.py](file:///media/ip-59/64GB/TeachAI/logger.py) хорошо структурирован для своих задач (JSON-файлы для действий, тестов, вопросов). Однако:

- При каждом событии он считывает весь JSON-файл, добавляет запись в список и перезаписывает весь файл (`_load_json_log` + `_save_json_log`). Для длинных курсов с множеством действий это становится O(n²) по операциям ввода-вывода.
- `log_lesson()` обрезает контент урока до 1000 символов — разумно, но «магическое число» стоит вынести в константу.

---

### 12. Паттерны промпт-инжиниринга

Промпты обширные и на русском языке (уместно для целевой аудитории). Основные наблюдения:

- **Повторение инструкций**: Одни и те же указания по форматированию (например, «КАЖДЫЙ ОПЕРАТОР НА ОТДЕЛЬНОЙ СТРОКЕ!», «НЕ ПИШИ КОД В ОДНУ СТРОКУ!») повторяются 5–8 раз в одном промпте в [lesson_generator.py](file:///media/ip-59/64GB/TeachAI/lesson_generator.py). Повторение может помочь, но такой уровень — избыточен и увеличивает расход токенов.
- **Комментарии Python попадают в промпты**: Строки вроде `# Ограничиваем длину для запроса` внутри f-строк отправляются в LLM как часть промпта.
- **Четверное экранирование скобок**: В [control_tasks_generator.py](file:///media/ip-59/64GB/TeachAI/control_tasks_generator.py) примеры JSON используют `{{{{` и `}}}}` для экранирования в f-строках. Это корректный Python, но трудно читаемый. Стоит рассмотреть `str.format()` или `string.Template` для построения промптов.
