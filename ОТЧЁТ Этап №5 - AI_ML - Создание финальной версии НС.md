## Вступление. Как читать этот этап

TeachAI — **inference-система** на готовой LLM (OpenAI API / совместимый шлюз).  
В проекте **нет** обучения собственной НС, **нет** fine-tuning, **нет** обучающей базы  
(это согласовано на этапах №2–№4; см. `Об отсутствии сбора базы и дообучения.md`, отчёт Этапа №4).

Поэтому критерии этапа №5 выполняются **адаптацией терминов**, без имитации несуществующего цикла обучения

| Формулировка задания | Аналог в TeachAI |
|----------------------|------------------|
| обучение модели / history | **не применимо**; вместо этого — **экспериментальный выбор готовой модели** (`Model_Benchmark.ipynb`) |
| loader / предобработка | сбор контекста и messages для Chat Completions |
| предсказание | генерация текста/JSON через API |
| точность / лучшая модель (точность ÷ параметры) | **балл судей / цена / latency** (`score_per_ruble`) |
| веса локально | не хранятся — модель на стороне провайдера |

«Функция» в задании = функция / класс / модуль. Основная логика — в `.py`, ноутбуки — точки входа.

## 2. Первый ноутбук — финальная версия (`TeachAI.ipynb`)

### 2.1. Friendly user interface

Интерфейс на **ipywidgets**. Пользователю без знания кода достаточно:

1. Скопировать `.env.sample` → `.env`, указать `OPENAI_API_KEY`.
2. Установить зависимости: `pip install -r requirements.txt`.
3. Открыть `TeachAI.ipynb` и выполнить **ячейку запуска**.
4. В UI ввести имя, параметры обучения, стиль общения; пройти урок / задать вопрос.

Тестовые данные вводятся через виджеты (не Colab upload) — проект рассчитан на локальный Jupyter.  
Смысл критерия («ввести свои данные → получить понятный вывод») сохранён.

### 2.2. Главная функция запуска

Последняя кодовая ячейка:

```python
from run_teachai import start_jupyter

start_jupyter()
```

Точка входа: `run_teachai.start_jupyter()` → `TeachAIEngine.start()` (`engine.py`).

### 2.3. Разбиение на «функции» (соответствие a–h)

| Критерий | Реализация | Где |
|----------|------------|-----|
| a. Загрузка файла | `.env`, `courses.json`, состояние пользователя | `ConfigManager`, `StateManager` |
| b. Очистка | санитизация ввода / примеров | `examples_code_fixes`, проверки валидаторов |
| c. Предобработка | профиль + стиль + тема → промпт | `LessonGenerator` и др. |
| d. Loader | список `messages` для API | `BaseContentGenerator.make_api_request` |
| e. Получение модели (`preload`) | клиент API + `LLM_MODEL` (веса не грузятся) | `content_utils.py` |
| f. Обучение | **не применимо** → inference + выбор модели в ноутбуке 2 | — |
| g. Постобработка / вывод | валидация JSON/кода, HTML, UI | валидаторы, `lesson_display`, `interface` |
| g′. Графики history | нет обучения; графики — в `Model_Benchmark.ipynb` | ноутбук 2 |

Пути — параметры с default (`ConfigManager(env_file=".env")` и др.).  
Чистые функции/методы: генераторы и валидаторы принимают данные аргументами.

### 2.4. Файлы рядом с ноутбуком

Модули `.py`, `courses.json`, `.env.sample`, `requirements.txt`.  
Локальных весов модели **нет** (облачный API).  
Для бенчмарка sample результатов лежит в `model_benchmark/results/`.

## 3. Второй ноутбук — эксперименты (`Model_Benchmark.ipynb`)

### 3.1. Зачем этот ноутбук вместо «эпох и нейронов»

Классический перебор архитектур на своих весах в проекте невозможен.  
Экспериментальный слой этапа №5 — **сравнение готовых LLM** на типовых промптах TeachAI  
с заранее зафиксированной рубрикой и LLM-as-judge (3 судьи из разных семейств).

Это закрывает требование общих правил к LLM-проектам:  
**экспериментальное обоснование выбора параметров / модели**  
(без выдуманного обучения «для галочки»).

### 3.2. Что сделано

| Параметр | Значение |
|----------|----------|
| Курс | Основы Python |
| Сценарии | 5 тем уроков (`scenarios/lessons.json`) |
| Участники | `gpt-4o-mini`, `gpt-5.6-luna`, `gpt-5.6-terra`, `claude-5-sonnet`, `gemini-3.5-flash` |
| Судьи | `gpt-5.6-sol`, `claude-opus-5`, `gemini-3.1-pro` |
| Шлюз | GPTunnel |
| Дата полного прогона | 13.09.2026 |
| Сырые данные | `model_benchmark/results/lesson_benchmark_20260913_123645.json` |

Ноутбук разбит на функции (`load_benchmark_report`, `plot_*`, `print_verdict`, …),  
отдельные ячейки на эксперименты A–D, графики, итоговый вердикт.  
По умолчанию читает **сохранённый JSON** (воспроизводимо без API).  
Живой повтор — опционально (`RUN_LIVE=True`).

### 3.3. Главный результат полного прогона

| Место | Модель | Балл (0–10) | ₽/урок | Балл/₽ | Latency |
|------:|--------|------------:|-------:|-------:|--------:|
| 1 | gpt-5.6-luna | **8.40** | 0.88 | 9.57 | ~84 с |
| 2 | gemini-3.5-flash | 8.33 | 6.53 | 1.28 | ~21 с |
| 3 | gpt-5.6-terra | 8.27 | 8.78 | 0.94 | ~82 с |
| 4 | **gpt-4o-mini** | 7.73 | **0.53** | **14.72** | **~12 с** |
| 5 | claude-5-sonnet | 7.67 | 7.57 | 1.01 | ~37 с |

Format gate: **25/25** генераций прошли.

Подробности методики, обрезка текста для судей (~3500 символов), голосование судей —  
в `ОТЧЁТ - Бенчмарк моделей LLM для TeachAI.md`.

### 3.4. Вердикт: какая «лучшая» конфигурация

**Приоритеты учебного проекта (зафиксированы до интерпретации):**

1. экономическая эффективность (`score_per_ruble`);
2. приемлемое абсолютное качество;
3. низкая цена и latency массовой генерации;
4. прохождение format gate.

**Решение:** базовую модель **`gpt-4o-mini` оставляем** в финальной системе (`LLM_MODEL` в `.env.sample`).

| Вопрос | Ответ |
|--------|--------|
| Меняем default? | **Нет** |
| Почему | лучший балл/₽, минимальная цена и latency, качество ~7.7/10 достаточное |
| Апгрейд при бюджете | **`gpt-5.6-luna`** (лидер по абсолютному качеству при цене ~1 ₽/урок) |
| Не берём для массовых уроков | Terra, Claude Sonnet 5, Gemini 3.5 Flash |

Аналог «точность / число параметров»: здесь **качество / цена / скорость**.  
Формальной ML-accuracy нет — это ограничение архитектуры, не скрытый провал эксперимента.

### 3.5. Соответствие критериям второго ноутбука

| Требование | Как закрыто |
|------------|-------------|
| Воспроизводимость | сохранённый JSON + функции загрузки; live-прогон опционален |
| Данные рядом | `model_benchmark/results/*.json`, сценарии, конфиг |
| Код функциями, без дубля | функции в ноутбуке + модуль `model_benchmark/` |
| Эксперименты в разных ячейках | A format gate / B качество-цена / C рубрика / D дым vs полный |
| Графики | качество, цена, балл/₽, latency, pedagogy vs task_fit |
| Вывод + лучшая конфигурация | раздел 7 ноутбука + `print_verdict` |
| Достигнута ли «точность» | да на уровне целевого ориентира учебного TI; оговорки протокола указаны |

## 5. Инструкция для запуска

```bash
git clone git@github.com:Ip-59/TeachAI.git
cd TeachAI
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.sample .env
# в .env: OPENAI_API_KEY=...

jupyter notebook TeachAI.ipynb          # финальная система
jupyter notebook Model_Benchmark.ipynb  # эксперименты (без ключа GPTunnel)
```

Для `Model_Benchmark.ipynb` достаточно выполнить ячейки сверху вниз:  
результаты читаются из `model_benchmark/results/`.  
Ключ `GPTUNNEL_API_KEY` нужен **только** если включить `RUN_LIVE=True`.

   это противоречит архитектуре и уже принятым этапам №2–№4.  
   Сдача этапа №5 выруливается честной адаптацией критериев + реальным сравнительным экспериментом.
