## 1. Цель

Сейчас выбор маршрута API (`direct` / `gptunnel` / `proxy`) показывается на учебном дашборде. Это временное решение для локальной настройки Игоря. Студент не должен видеть и настраивать маршрутизацию API ни на одном учебном экране.

Нужно:
- задавать маршрут в `TeachAI.ipynb` технической ячейкой **до** ячейки Start;
- применять его до инициализации приложения и до создания API-клиента;
- полностью убрать выбор и показ маршрута из учебного UI.

Не входит в задачу: проектирование продакшен-инфраструктуры, чистка остальной документации и ссылок, исправления релевантности (контекст курса, страховка 7c).

## 2. Карта по просмотренному коммиту (сверить с HEAD)

- `TeachAI.ipynb`: импортирует `run_teachai.start_jupyter` и вызывает её.
- `run_teachai.start_jupyter()` по порядку: `load_dotenv(override=True)` → `apply_openai_connection_environment()` → вывод описания подключения → `TeachAIEngine()` → `engine.start()`.
- `engine.start()`/`initialize()` создают config и `ContentGenerator`, а с ним OpenAI-клиент. Это происходит **до** показа дашборда.
- `startup_dashboard.show_dashboard()` создаёт `route_selector` через `llm_route.make_route_selector_widget()` и добавляет его в макет. Callback «Продолжить» вызывает `set_llm_route(..., persist=True)`.
- `llm_route` отвечает за выбор маршрута, конфигурацию клиента и сохранённые настройки (preferences).

Следствие: если просто присвоить `os.environ[...]` в ячейке ноутбука, значение будет перезаписано вызовом `load_dotenv(override=True)` внутри `start_jupyter`, если ключ есть в `.env`. Кроме того, маршрут может перечитываться или кэшироваться в config, preferences и при создании клиента. Поэтому одной ячейки с env недостаточно.

## 3. Требуемое поведение

### 3.1. Ячейка ноутбука (один вариант, без альтернатив)

Перед ячейкой Start добавь одну короткую техническую ячейку (markdown-пояснение + код), например так:

```python
# Техническая настройка запуска (для разработчика, не для студента).
# None — использовать текущую настройку (.env / окружение / сохранённая / по умолчанию).
# Либо одна из строк: "direct", "gptunnel", "proxy".
API_ROUTE = None
```

Затем значение передаётся в запуск. Механизм выбирает Cursor, и он должен быть минимальным реальным: например, новый необязательный аргумент `start_jupyter(api_route=API_ROUTE)` либо существующий подходящий setter, вызванный в правильный момент. Ячейка выше — концепция, а не готовый API.

Требования к ячейке:
- никаких ключей, токенов и URL с секретами;
- никаких закомментированных альтернатив и вариантов «выбери сам»;
- никаких виджетов выбора маршрута;
- без подписей вида «direct = VPN/дома»;
- без `gptunnel` по умолчанию. Значение по умолчанию в ячейке — `None`. Игорь локально использует gptunnel, `GPTUNNEL_API_KEY` и gpt-4o-mini, но это не продуктовый default.

### 3.2. Приоритет и применение

- Явный маршрут из ноутбука применяется **после** всех загрузок `.env` (включая `load_dotenv(override=True)`) и **до** всего, что читает или кэширует маршрут: проверки готовности, config, `ContentGenerator`, конструктора клиента.
- Явный маршрут побеждает. Проверь все места, где маршрут перечитывается: повторные `load_dotenv`, `apply_*`, preferences, кэши. Если явный маршрут где-то теряется — исправь precedence.
- При `None` сохраняется **существующая** семантика `.env`, окружения, preference и значения по умолчанию. Сначала выясни её по коду и не придумывай новый порядок.
- При повторном запуске с `None` предыдущее значение из ноутбука сбрасывается: ни в `os.environ`, ни в кэше модулей не остаётся устаревший маршрут. Восстанавливается поведение «как без ноутбука».
- Повторное нажатие Start в том же kernel с другим маршрутом создаёт новый, правильно настроенный клиент. Перезапуск kernel не нужен, UI не дублируется. Автоматически перезапускать уже работающее приложение без нового запуска Start не нужно.
- Недопустимое значение (не `None` и не одна из трёх строк) — явная понятная ошибка до запуска UI. Тихой замены на default быть не должно.
- Выбор в ноутбуке **не** пишет `.env` и **не** сохраняет постоянную preference как побочный эффект. Существующие локальные preferences Игоря остаются нетронутыми.
- Названия маршрутов, их семантика и backend-настройки остаются точно такими же, как сейчас.

### 3.3. Учебный UI

- Убери из `startup_dashboard` создание, показ и сохранение маршрута (`route_selector` и запись маршрута в callback «Продолжить»). Остальное поведение кнопки сохраняется.
- Ни на одном учебном экране не должно быть выбора маршрута, бейджей, статусов и названий провайдера или маршрута. Проверь поиском и другие экраны, а не только дашборд.
- Технические сообщения о маршруте допустимы только в выводе настроечной части ноутбука, до учебного UI.
- Не скрывай подряд все реальные ошибки приложения. Нужно убрать только UI маршрутизации.

### 3.4. Ошибки и секреты

- Не печатай `repr` исключений и значения env, если там может оказаться ключ. В сообщениях указывай только имя отсутствующей переменной.
- Проверка учётных данных до запуска — офлайн: наличие и, если это уже поддерживается кодом, формат. Без реальных запросов к API. Сообщения не должны обещать доступность сети.
- Читать или выводить секреты для выполнения задачи не нужно.

### 3.5. `llm_route` / config

Их можно менять **узко**, если это нужно для precedence, сброса или пересоздания клиента. Удалять код маршрутов, если его используют другие места, нельзя. `make_route_selector_widget` удаляй только если он больше нигде не используется. Если сомневаешься — оставь его.

### 3.6. Запуск без Jupyter

Новая конфигурация не должна добавлять зависимость от IPython или ipywidgets в пути запуска без ноутбука и не должна ломать существующий запуск из CLI. Не утверждай, что существующий CLI работает без виджетов, пока не проверишь это.

## 5. Тесты (требования, а не готовый код)

Изолируй всё: временные директории и файлы для preference, monkeypatch env, подмена или мок `load_dotenv` и конструктора клиента. Никаких сетевых вызовов, никакого реального `.env` и `data/`. Проверяй реальные kwargs или конфигурацию построенного клиента (base_url, ключ из нужной переменной, proxy/http-клиент — по факту кода), а не только `route in (...)`.

Обязательные случаи:
1. `None` без env и preferences → **точно** существующий default (определи по коду).
2. `None` при заданных env / preference → существующая семантика без изменений.
3. Явный `direct`, `gptunnel`, `proxy` → у клиента соответствующие параметры.
4. Регрессия: `.env` с другим маршрутом и `load_dotenv(override=True)` не перебивают явный маршрут.
5. Недопустимое значение → явная ошибка, клиент не создаётся.
6. Отсутствуют обязательные учётные данные выбранного маршрута → понятная ошибка без значений секретов.
7. Два последовательных запуска с разными маршрутами в одном процессе → второй клиент с новым маршрутом.
8. Явный маршрут, затем `None` → устаревший маршрут сброшен.
9. Выбор в ноутбуке не меняет preference-файл и `.env` (на временных копиях).
10. Дашборд не создаёт и не показывает виджет маршрута (если в проекте уже есть подходящий подход к тестированию UI).

Запусти полный набор тестов в venv текущей машины. Зелёным должно быть всё, без новых skip/xfail.

## 6. Ручная проверка (Игорь в Jupyter)

- `API_ROUTE = None` → Start → обучение работает так же, как до изменения; на дашборде маршрута нет.
- Явный маршрут, которым Игорь пользуется локально → Start → работает.
- Сменить значение и снова Start в том же kernel → применился новый маршрут, дублей UI нет.
- Недопустимая строка → понятная ошибка до UI, секретов в выводе нет.
