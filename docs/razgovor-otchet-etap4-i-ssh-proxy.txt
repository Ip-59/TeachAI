# ОТЧЁТ  
## Этап №4 | AI/ML | Создание прототипа НС и получение первой точности распознавания  

**Проект:** TeachAI — интеллектуальная система персонализированного обучения  
**Автор:** Игорь Пучкин  
**Дата:** 28.05.2026  

---

## 1. Тема и описание задачи

**Тема:** прототип AI-системы на основе предобученной языковой модели (LLM) для автоматической генерации и контроля качества образовательного контента.

**Описание задачи.**  
TeachAI — прикладная inference-система: она не обучает собственную нейросеть с нуля и не выполняет fine-tuning. Используется готовая GPT-модель (OpenAI API) для:

- генерации плана курса, уроков, примеров кода, тестов;
- ответов на вопросы студента в рамках урока;
- проверки релевантности вопросов теме урока;
- валидации и автокоррекции сгенерированного контента.

**Постановка «точности распознавания» в контексте проекта.**  
Классический этап №4 (обучение CNN/классификатора на своей выборке) к TeachAI **не применим**: нет обучающей базы изображений/текстов для дообучения (см. этапы №2–№3). Вместо accuracy классификатора на эпохах обучения в отчёте фиксируются **операционные метрики качества inference-прототипа**:

| Задача «распознавания» в TeachAI | Что оценивается |
|----------------------------------|-----------------|
| Структурная валидность плана курса | Доля планов с корректной JSON-структурой |
| Качество примеров кода | Доля примеров, прошедших синтаксическую и семантическую проверку |
| Релевантность вопросов | Корректность решения `is_relevant` (модуль `relevance_checker.py`) |
| Усвоение материала пользователем | Оценки в контрольных заданиях (модуль `assessment`) |

Такой подход соответствует современной практике: сначала prompt engineering и валидация на inference, fine-tuning — только при доказанной необходимости (OpenAI Prompt Engineering / Fine-Tuning Guide).

## 2. База данных

### 2.1. Обучающая база для НС — отсутствует (обоснованно)

По архитектурному решению проекта (этапы №2–№3):

- **не собирается** размеченная обучающая выборка;
- **не выполняется** дообучение GPT;
- **не используется** парсинг внешних источников для формирования датасета.

Причины (кратко):

1. Задачи решаются промпт-инженерией, валидацией и перегенерацией без fine-tuning.  
2. Масштаб дипломного проекта недостаточен для значимого улучшения модели (<10 000 качественных примеров).  
3. Этические и организационные ограничения на сбор пользовательских диалогов.  
4. Экономика: fine-tuning GPT требует отдельного формата данных и существенных затрат.

**Вывод для отчёта:** раздел «База» в классическом ML-смысле **не применим**; конфиденциальных обучающих данных нет, потому что их **нет по замыслу системы**.

### 2.2. Операционные данные (не для обучения НС)

| Источник | Назначение |
|----------|------------|
| Профиль и прогресс (`state_manager.py`, JSON) | Персонализация, сохранение уроков и оценок |
| Промпты в генераторах (`lesson_generator.py`, `course_plan_generator.py` и др.) | Параметризация запросов к API |
| Логи (`logs/teachai.log`) | Отладка, учёт ошибок API и валидации |
| `.env` | API-ключ, модель (`LLM_MODEL`), прокси |

Эти данные **не используются** для gradient descent / fine-tuning.

---

## 3. Параметризация данных

В TeachAI «параметризация» — это **настройка входа inference**, а не аугментация изображений или нормализация тензоров.

### 3.1. Параметры пользователя и курса

- имя, общее время обучения, длительность урока;
- стиль общения: `formal` | `friendly` | `casual` | `brief`;
- выбранный курс, текущий урок, история тестов.

### 3.2. Параметры запросов к LLM

| Параметр | Типичное значение | Назначение |
|----------|-------------------|------------|
| `LLM_MODEL` | `gpt-4o-mini` (по умолчанию) | Базовая модель |
| `temperature` | 0.7 — генерация контента; 0.2 — проверка релевантности | Креативность vs. стабильность |
| `max_tokens` | до 3500 | Ограничение длины ответа |
| `response_format` | `{"type": "json_object"}` | Структурированный вывод (планы, релевантность) |

Реализация: `content_utils.py`, метод `make_api_request`.

### 3.3. Структурная параметризация контента

- JSON-схемы плана курса (разделы → темы → уроки);
- список примеров `{"title", "description", "code"}` с правилами в `examples_validation.py` (минимум 3 примера, ≥3 строк кода, запрет JS/HTML-маркеров);
- проверка Python через `ast` (синтаксис без выполнения).

### 3.4. Параметры контроля качества

- пороги валидации плана (`course_plan_generator.py` → `_validate_and_fix_course_plan`);
- эвристики релевантности (`relevance_checker.py`, словарь базовых тем Python);
- перегенерация при провале валидации (`validate_and_regenerate_if_needed`).

## 4. Архитектура нейросети

### 4.1. Используемая НС (внешняя, предобученная)

**Модель:** GPT (семейство decoder-only Transformer), доступ через OpenAI Chat Completions API.

Упрощённая схема (концептуально):

```
Вход: токенизированный промпт (system + user messages)
  → Embedding
  → N × (Multi-Head Self-Attention + Feed-Forward + Layer Norm)
  → LM Head
  → вероятностное предсказание следующего токена
  → текст / JSON на выходе
```

Веса модели **не обучаются в проекте**; обучение выполнено производителем (pre-training + RLHF на стороне OpenAI).

### 4.2. Архитектура программного прототипа TeachAI

```
TeachAIEngine (engine.py)
    ├── ConfigManager, StateManager
    ├── ContentGenerator (фасад)
    │     ├── CoursePlanGenerator
    │     ├── LessonGenerator
    │     ├── ExamplesGenerator + ExamplesValidation
    │     ├── AssessmentGenerator
    │     ├── QAGenerator
    │     └── RelevanceChecker
    ├── Assessment (проверка знаний)
    └── UI (ipywidgets, Jupyter)
```

**Точка входа:** `run_teachai.py`, `TeachAI.ipynb`.

Прототип — это **оркестрация inference** + **постобработка**, а не отдельно обученный классификатор.

## 7. Выводы

1. **Прототип создан и работает** — TeachAI демонстрирует полный цикл: настройка профиля → план курса → урок → примеры → тесты → Q&A с проверкой релевантности.

2. **Собственная НС не обучалась** — осознанное архитектурное решение; используется предобученная GPT с prompt engineering и многоуровневой валидацией.

3. **Первая «точность» зафиксирована** через операционные метрики (~95% / ~90% / ~85%), что для генеративной образовательной системы эквивалентно baseline на этапе прототипирования.

4. **Подход масштабируем и гибок** — смена предметной области не требует переобучения; достаточно изменить промпты и правила валидации.

5. **Ограничения:** зависимость от API и сети; стохастичность LLM; метрики основаны на ограниченном ручном тестировании, а не на размеченном hold-out датасете из тысяч примеров.

## Чего в проекте нет

- Нет `test_*.py` / скриптов, которые считают эти проценты по выборке.
- Нет логов вида «N запусков → M успешных» в репозитории как источника для таблицы.

## Что такое `run_teachai.py`

Это **не ядро проекта**, а **тонкая обёртка** (~115 строк) для запуска. Вы её не заказывали — по git она появилась при рефакторинге (вместо удалённого `main.py`), её добавили в README и в ячейку ноутбука.

**Что делает:**

| Функция | Назначение |
|---------|------------|
| `start_jupyter()` | Загружает `.env` → создаёт `TeachAIEngine()` → вызывает `engine.start()` → возвращает виджет UI для Jupyter |
| `reload_project_modules()` | При разработке перезагружает `.py` в kernel без Restart (опционально, `reload_modules=True`) |
| `main()` | Запуск из терминала: `python run_teachai.py` — та же инициализация, но **без полноценного GUI** (ipywidgets рассчитаны на Jupyter) |

Вся логика — в **`engine.py`** (`TeachAIEngine`). `run_teachai.py` только вызывает её.

**Работает ли?** Да, если настроены `.env`, API и зависимости. Сейчас в `TeachAI.ipynb` стоит:

```python
from run_teachai import start_jupyter
start_jupyter()
```

По сути то же самое можно написать напрямую:

```python
from dotenv import load_dotenv
from engine import TeachAIEngine

load_dotenv()
engine = TeachAIEngine()
interface = engine.start()
display(interface)  # если нужен явный display
```

**Нужен ли он?** Не обязателен. Удобен как «одна строка в ноутбуке» и для `reload` при правках модулей. Для отчёта достаточно **`TeachAI.ipynb` + `engine.py`**.

Если хотите убрать файл из проекта — можно переписать ячейку ноутбука на прямой импорт `engine` и удалить `run_teachai.py` из README. Могу сделать это по запросу.

Проверка SSH для GitHub — по шагам в терминале.

### 1. Есть ли ключи

```bash
ls -la ~/.ssh
```

Ищите файлы вроде:
- `id_ed25519` и `id_ed25519.pub` (предпочтительно)
- или `id_rsa` и `id_rsa.pub`

Если папки нет или только `known_hosts` — ключей, скорее всего, нет.

### 2. Загружен ли ключ в агент (не всегда обязательно)

```bash
ssh-add -l
```

- Список ключей — ок.
- `The agent has no identities` — ключ не добавлен: `ssh-add ~/.ssh/id_ed25519`
- `Could not open a connection to your authentication agent` — агент не запущен (на Linux часто не нужен, если ключ без passphrase).

### 3. Работает ли доступ к GitHub по SSH

```bash
ssh -T git@github.com
```

Ожидаемо при **успехе**:
```text
Hi Ip-59! You've successfully authenticated...
```
(имя пользователя GitHub может быть другим)

При **проблемах**:
- `Permission denied (publickey)` — ключ не создан или не добавлен в GitHub
- `Connection timed out` — сеть/фаервол блокирует порт 22

### 4. Настроен ли remote репозитория на SSH

```bash
cd /media/ip-59/64GB/TeachAI
git remote -v
```

Для SSH должно быть так:
```text
origin  git@github.com:Ip-59/TeachAI.git (fetch)
origin  git@github.com:Ip-59/TeachAI.git (push)
```

Если `https://github.com/...` — push идёт по HTTPS, не по SSH (нужен токен, не SSH-ключ).

Переключить на SSH:
```bash
git remote set-url origin git@github.com:Ip-59/TeachAI.git
```

### 5. Добавлен ли ключ в GitHub (если ключ есть, а `ssh -T` не пускает)

Показать публичный ключ и скопировать в буфер (Linux):
```bash
cat ~/.ssh/id_ed25519.pub
```

GitHub → **Settings** → **SSH and GPG keys** → **New SSH key** → вставить содержимое `.pub`.

# Настройка SSH для GitHub (Linux)

Пошагово: ключ → GitHub → проверка → push TeachAI.

---

## 1. Создать SSH-ключ

```bash
ssh-keygen -t ed25519 -C "ваш_email@example.com" -f ~/.ssh/id_ed25519
```

- На вопрос про passphrase: Enter (пусто) или задайте пароль — безопаснее с паролем.
- Появятся `~/.ssh/id_ed25519` (секретный) и `~/.ssh/id_ed25519.pub` (публичный).

---

## 2. Запустить ssh-agent и добавить ключ (если задали passphrase)

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

---

## 3. Скопировать публичный ключ в GitHub

Показать ключ:

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопировать **всю строку** (от `ssh-ed25519` до email).

В браузере:

1. [github.com](https://github.com) → аватар → **Settings**
2. **SSH and GPG keys** → **New SSH key**
3. Title: например `TeachAI laptop`
4. Key: вставить скопированное → **Add SSH key**

---

## 4. Проверить подключение

```bash
ssh -T git@github.com
```

При первом подключении: `Are you sure...` → напишите `yes`.

Успех:
```text
Hi Ip-59! You've successfully authenticated, but GitHub does not provide shell access.
```

---

## 5. Переключить репозиторий TeachAI на SSH

```bash
cd /media/ip-59/64GB/TeachAI

git remote set-url origin git@github.com:Ip-59/TeachAI.git

git remote -v
```

Должно быть `git@github.com:Ip-59/TeachAI.git`, не `https://...`.

---

## 6. Push (прокси выключен)

```bash
unset HTTP_PROXY HTTPS_PROXY ALL_PROXY OPENAI_PROXY

git push origin main
```

Отправятся все **6** локальных коммитов, в том числе с отчётом по этапу №4.

---

## Если что-то не работает

| Ошибка | Что сделать |
|--------|-------------|
| `Permission denied (publickey)` | Ключ не добавлен в GitHub или не тот аккаунт — повторите шаги 3–4 |
| `Connection timed out` на порту 22 | Фаервол блокирует SSH; попробуйте HTTPS + [token](https://github.com/settings/tokens) |

Это сообщение **не про ваш проект TeachAI** и **не про прокси OpenAI в `.env`**. Оно от **Cursor IDE**: выбранная модель (провайдер) **недоступна в вашем регионе** по правилам самого провайдера (OpenAI, Anthropic и т.д.).

## Что это значит

Cursor подключается к моделям через своих партнёров. У них есть **географические ограничения** — для части стран/регионов некоторые модели отключены. Тогда Cursor пишет:

> *This model provider is not supported in your region*

Подробности: [cursor.com/docs/account/regions](https://cursor.com/docs/account/regions)

## Почему прокси часто не помогает

| Прокси для | Что решает |
|------------|------------|
| **`.env` → OpenAI API** (TeachAI, `196.18...`) | Запросы **вашего кода** к `api.openai.com` |
| **Cursor AI / чат / Agent** | Отдельный канал: биллинг аккаунта Cursor, регион аккаунта, политика провайдера |

Прокси в TeachAI **не перенаправляет** запросы Cursor к Claude/GPT внутри редактора. Cursor обычно смотрит на **регион аккаунта/оплаты и политику провайдера**, а не на ваш HTTP_PROXY для Python.

## Что можно сделать в Cursor

1. **Другая модель** — в выборе модели взять **Auto** или ту, что **не** заблокирована в вашем регионе.
2. **Свой API-ключ** — *Settings → Models → API Keys* (если провайдер пускает ваш регион даже с ключом; иначе снова будет ошибка).
3. **Другой провайдер** — если Claude недоступен, попробовать модель от другого партнёра из списка в Cursor.
4. **VPN** — иногда меняет доступ, но **не гарантия**: Cursor может опираться на регион аккаунта, не только на IP.

## Связь с TeachAI

- **TeachAI + прокси + `OPENAI_API_KEY`** — отдельная история; если API у вас через прокси работает, проект может работать **независимо** от того, какая модель доступна в Cursor.
- Ошибка в Cursor **не значит**, что TeachAI сломан.

## Кратко

**«Model provider is not supported in your region»** = Cursor не может использовать **эту** модель у **этого** провайдера в вашем регионе. Прокси для OpenAI в проекте это **не исправляет**. Выберите другую модель в Cursor, Auto, или свой API-ключ — если провайдер разрешает ваш регион.

## Как Cursor «видит» регион

| Фактор | Влияние |
|--------|---------|
| **Внешний IP** при запросах к Cursor | **Главное** — по нему провайдеры моделей решают, пускать или нет |
| **VPN / системный прокси / Clash и т.п.** | Если Cursor ходит через них — страна **exit IP прокси**, не «физическое» местоположение |
| **Прокси только в `.env` для OpenAI** | На Cursor **не влияет** — это другой трафик |
| **Страна аккаунта / оплаты** | Может иметь значение, но в спорных случаях на форуме Cursor упирают в **IP и маршрутизацию** |

## Как узнать «свою страну» для Cursor (практически)

### 1. IP в браузере (грубая проверка)

Откройте в **том же браузере/с той же VPN**, что используете для работы:

- https://ipinfo.io  
- или https://ifconfig.me/all  

Там будет **country** и IP. Это **не 100% то же**, что видит Cursor, но ориентир.

### 2. Диагностика в Cursor

**Cursor Settings → Network → Run Diagnostics**

Проверяет связь с серверами Cursor. Если в логах/SSL видно `127.0.0.1` — трафик идёт через **локальный прокси** (Clash, V2Ray и т.д.), и Cursor может видеть **другой exit IP**, чем «простой» ipinfo в браузере.

Документация: [Network troubleshooting](https://cursor.com/help/troubleshooting/network)

### 3. Сравнить: браузер vs Cursor

Частая ситуация:

- в браузере ipinfo → **Япония / UK** (VPN включён);
- Cursor **не** через VPN / через другой прокси → сервер видит **другую страну** → ошибка *not supported in your region*.

На [форуме Cursor](https://forum.cursor.com/t/why-am-i-being-informed-that-the-model-is-unavailable-even-though-it-is-available-in-the-applicable-area/155652) пишут: даже если ipinfo показывает «хорошую» страну, **exit IP для `cursor.com` может быть другим**.

### 4. Ваш прокси `196.18.237.218:8000`

Он для **OpenAI API в TeachAI**. Чтобы узнать **его** страну:

```bash
curl -x http://<логин>:<пароль>@196.18.237.218:8000 https://ipinfo.io/json
```

(подставьте свои логин/пароль из `.env`)

Это страна для **API**, не обязательно для **Cursor**, если Cursor этот прокси не использует.

---

## Что сделать, если нужно понять именно Cursor

1. **Выключить** системный прокси / VPN → перезапустить Cursor → снова ipinfo.io → попробовать модель.  
2. **Включить** VPN в **TUN/global mode** (чтобы **весь** трафик, включая Cursor, шёл через VPN) → перезапуск Cursor.  
3. Или наоборот: добавить `*.cursor.com`, `*.cursor.sh` в **обход прокси** (direct), если прокси даёт «запрещённый» exit IP.

## Краткий вывод

- **Узнать «страну в Cursor» одной кнопкой нельзя** — только косвенно: IP + диагностика + эксперiment с VPN/прокси.  
- Cursor смотрит на **IP запросов к своим серверам**, не на прокси из `.env` TeachAI.  
- Ошибка *This model provider is not supported in your region* значит: для **этого** провайдера Cursor считает ваш **effective IP** из **ограниченного** региона.

Если напишете: **VPN/системный прокси включён или нет** и что показывает `curl https://ipinfo.io/json` **без** прокси и **с** вашим прокси — можно сузить, почему Cursor ругается, а TeachAI через API может работать.
