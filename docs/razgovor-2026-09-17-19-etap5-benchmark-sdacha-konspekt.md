## 1. Исходная постановка (начало линии, ~13–16.09)

### 1.1. Запрос пользователя

Сделать отдельный подпроект/модуль, цель которого — **обосновать выбор нейросетей**, используемых в TeachAI. Выбор ChatGPT (дешёвая / более умная модель) был сделан произвольно. Нужен **тестер-имитатор** (не полный дубль TI): одинаковые типичные промпты → несколько известных моделей → сравнение ответов → вывод: выбранная модель оптимальна / достаточна / стоит сменить.

Пользователь просил относиться **критически**, как партнёр, а не соглашаться со всем.

### 1.2. Позиция агента (критический дизайн)

Риски «пост-факт обоснования ChatGPT». Нужно:
- зафиксировать критерии **до** прогона;
- тестировать не «общий чат», а сценарии TI (уроки JSON/markdown, русский, валидация, цена, latency);
- модуль внутри проекта (`model_benchmark/`), не мегапроект;
- шлюз к нескольким моделям (сначала думали OpenRouter, затем **GPTunnel** — ключ уже был);
- оценка: рубрика + **LLM-as-judge**, не «на глаз».

Пользователь уточнил: оценивать **содержание урока**; неверный формат — отсев; смысл — 1–3 старшие модели-судьи.

### 1.3. Реализованный дизайн (зафиксирован в SPEC)

См. `model_benchmark/SPEC.md`, `config.json`, `rubric.json`.

**Курс MVP:** Основы Python (`python-basics`), стиль `friendly`.

**Критический сценарий первого полного прогона:** генерация текста урока (не весь TI).

**Участники (GPTunnel id):**

- `gpt-5.6-terra` — modern balanced
