### По пунктам

**1. Своё название курса**  
Логично: «нейроучитель» должен уметь тему вне каталога. Минимально: `Text` + опция «свой курс» рядом с dropdown → синтетический `course` (`id`, `title`, description) → тот же `generate_course_plan`. Не нужен отдельный CRUD каталога. Риск — качество плана на странных названиях; лечится валидацией длины/языка и промптом, не UI-магией.

**2. Несколько курсов / switch / delete**  
Самое архитектурно тяжёлое и самое правильное. Сейчас старт нового курса через `save_course_plan` / `update_learning_progress(course=...)` по сути **перетирает** один слот. Нужна модель вида `courses: {course_id: {plan, progress, lesson_cache, status}}` + `active_course_id`, UI «мои курсы», switch без wipe, delete с подтверждением.  
Осторожно: не плодить «второй LMS». Для защиты достаточно портфеля 2–N курсов в `state.json`, без синхронизации и без облака.

**3. Перемещение по урокам**  
Куратор прав: без карты курса система ощущается линейным квестом. Минимум: outline (раздел → тема → урок) + переход к выбранному + пометки done/current; «Назад/Вперёд» по плану. Не обязательно открывать любой урок без ограничений — можно: завершённые + текущий + следующий (или все с предупреждением). Иначе расползётся смысл прогресса и кэша.

**4. Вывод ответов LLM — здесь важно не согласиться с пафосом**  
Проблема реальная (смесь текста/кода/разметки в Jupyter HTML). Но формулировка «ИИ уже живёт, а мы не можем вывести на экран» толкает к **overengineering**.

Два ваших документа **не полностью согласованы**:
- Perplexity тянет к «всё в JSON-конверте + блоки».
- Mistral (более зрелый вывод) — **гибрид**: учебный текст = Markdown + нормальный рендерер; тесты/план/метаданные = Structured Outputs (`json_schema`).

Для TeachAI верный якорь — **гибрид Mistral**, адаптированный под **ipywidgets**, а не react-markdown / Streamdown:
- урок / объяснение / Q&A prose → Markdown → единый `render_markdown_to_html` (без самописных «очистителей», где можно);
- план, вопросы теста, примеры как данные → schema + валидация (у вас часть уже есть для примеров);
- картинки/Mermaid/image-gen — **не** в scope сдачи, если куратор явно не требует.

Полный rewrite пайплайна «везде» = риск сломать рабочий прототип перед защитой. Цель: **один контракт отображения** на всех экранах, а не смена стека.

**5. Перекликивание в тесте**  
Типичный дефект UX: ответы пишутся только в `observe`, а submit берёт `current_answers`. Надёжный фикс: перед проверкой снять `radio.value` из `question_widgets`. Мелочь, но куратор её видит сразу — делать первой.

**6. Принудительный переход к КЗ**  
Сейчас кнопка намеренно `disabled=not test_passed`. Force completion урока уже есть — это другое. Нужна отдельная политика: «Перейти к практике без теста» / «Пропустить тест» с пометкой в прогрессе (и честной формулировкой на защите: педагогический bypass, не обход оценки). Не путать с принудительным *завершением* урока.

Это не баг генерации теста: **OpenAI отклонил запрос по гео** (`unsupported_country_region_territory`). У вас в `.env` стоит `OPENAI_CONNECTION_MODE=direct` — приложение само прокси не включает и ждёт, что **весь трафик Python/Jupyter** пойдёт через VPN на уровне ОС.

Сейчас из терминала Cursor выход уже **London (GB)** — VPN для этой среды работает. Jupyter часто продолжает ходить «мимо» VPN (ядро запущено до VPN, split-tunnel, другой Python).

### Что сделать

1. **Перезапустить kernel** ноутбука (Kernel → Restart) уже при включённом VPN.
2. В первой ячейке проверить выходной IP **того же Python**, что крутит TeachAI:

```python
import urllib.request
print(urllib.request.urlopen("https://api.ipify.org", timeout=15).read().decode())
```

Нужна страна, которую OpenAI принимает (не РФ). Если IP российский — VPN Jupyter не покрывает.

3. При старте TeachAI в выводе должно быть:  
   `OpenAI: прямое подключение (без прокси в приложении; VPN/сеть на уровне ОС)`.

4. Если IP в ноутбуке всё ещё РФ — либо починить split-tunnel (весь трафик / `api.openai.com` через VPN), либо в `.env`:

```env
OPENAI_CONNECTION_MODE=proxy
OPENAI_USE_PROXY=true
OPENAI_PROXY=http://user:pass@host:port
```

(прокси в разрешённой стране; потом снова Restart kernel).

5. Если IP уже GB/EU, а 403 остаётся — смотреть **аккаунт OpenAI** (регион биллинга/организации), не код урока.

Итого: тест падает из‑за сети/региона до модели, не из‑за этапа 1. После проверки IP в ячейке напишите, что вывело — подскажем, direct или proxy.
