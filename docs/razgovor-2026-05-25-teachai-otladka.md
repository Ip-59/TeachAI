## 1. Экран знакомства — обрезанные подписи полей

**Пользователь:**  
Надо поправить экран знакомства — первого диалога системы со студентом. Нужно, чтобы строка умещалась или выполнялся перевод строки; потеря части текста неприемлема.

**Проблема:**  
На форме «Настройка профиля TeachAI» подписи полей обрезались: «Общее вр...», «Длительн...», «Стиль общ...».

**Причина:**  
У ipywidgets по умолчанию ширина подписи (~80px) фиксирована, длинный текст обрезается с многоточием.

**Исправление (файл `setup_interface.py`):**
- `description_width: "initial"` — ширина подписи подстраивается под текст;
- ширина строк формы увеличена до 520px;
- CSS для подписей: перенос строки, без `text-overflow: ellipsis`;
- класс контейнера `teachai-setup-form`.

**Рекомендация:** перезапустить kernel или ячейку ноутбука после изменений.

## 2. «Похоже, завис проект?»

**Пользователь:**  
Похоже, завис проект? В чём проблема?

**Диагностика:**  
По выводу ячейки TeachAI **не завис** — запуск дошёл до конца:
- `✅ Система TeachAI успешно инициализирована!`
- `✅ TeachAI запущен. Нажмите «Продолжить обучение».`
- в конце — текстовое представление виджета `VBox(children=...`

**Возможные причины ощущения «зависло»:**

1. **Долгий `pip install`** (TensorFlow и др.) — 10–15+ минут без заметного прогресса.
2. **Виджет показался как текст**, а не как форма — в Cursor/VS Code Jupyter ipywidgets иногда не рендерятся. Решение: `display(start_jupyter())`, kernel из `venv_W_L`.
3. **Полная инициализация при первом запуске** — секунды, не минуты.
4. **Зависание после «Продолжить обучение»** — генерация урока через OpenAI (прокси, сеть).
5. **Предупреждения** `No module named 'demo_cell_widget'` — не критично, образовательные ячейки отключены.

## 3. «Начать курс» — зависание на «Переход к первому уроку...»

**Пользователь:** (скриншот)  
Кнопка «Начать курс», сообщение «Переход к первому уроку...» — дальше ничего.

**Проблема:**  
В `setup_interface.py` после успешного поиска первого урока показывалось только сообщение «Переход к первому уроку...», а вызов `show_lesson()` оказался в **недостижимой ветке** (`elif` «курс завершён») **после `return`**.

**Исправление:**  
Код открытия урока перенесён в правильную ветку `if section_id and topic_id and lesson_id`: создаётся `LessonInterface`, вызывается `show_lesson()`, результат отображается через `display()`.

**Рекомендация:** перезапустить kernel, снова нажать «Начать курс». Дальше может идти генерация урока через API (десятки секунд — нормально).

## 4. Connection error при генерации учебного плана

**Пользователь:** (скриншот)  
Ошибка: «Не удалось сгенерировать учебный план: Connection error.»

**Причина:**  
При нажатии «Начать курс» система вызывает OpenAI API. `Connection error` — не удалось достучаться до API (прокси, интернет, недоступный прокси).

**Исправления в коде:**
1. Понятное сообщение вместо сырого `Connection error` (`interface_utils.format_api_error`).
2. Перенос длинного текста в цветных плашках (`word-wrap`, `overflow-wrap`).
3. Убран дублирующий `ERROR:` в интерфейсе (остаётся в debug-логе).
4. Три повторные попытки при генерации плана (`make_api_request_with_retries` в `course_plan_generator.py`).
5. Таймаут подключения 20 с в httpx.

**Что проверить в `.env`:**
```env
OPENAI_API_KEY=sk-...
OPENAI_PROXY=http://логин:пароль@хост:порт
```

## 5. VPN без прокси — ошибка «Прокси не задан»

**Пользователь:**  
Выключил прокси, включил VPN. Получил:
```
ERROR:config:Прокси не задан. Укажите OPENAI_PROXY или HTTPS_PROXY/HTTP_PROXY.
❌ ОШИБКА: Не удалось загрузить конфигурацию из .env файла!
```

**Причина:**  
TeachAI **требовал** прокси в `.env`, даже если VPN даёт доступ к OpenAI.

**Исправление:**  
Прокси стал **опциональным**:
- есть `OPENAI_PROXY` → через прокси;
- нет → прямое подключение (VPN на уровне системы).

**Рекомендация для `.env` при VPN:**
```env
OPENAI_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini
```
Строку `OPENAI_PROXY` удалить или закомментировать. **Перезапустить kernel.**

## 6. Явный переключатель режима: прокси или VPN/direct

**Пользователь:**  
Надо на период отладки иметь возможность указывать: либо через прокси с OpenAI, либо без прокси с VPN на уровне системы.

**Ответ:** Да, возможно. Добавлена переменная **`OPENAI_CONNECTION_MODE`** в `.env`.

### Значения

| Значение | Поведение |
|----------|-----------|
| **`direct`** | Без прокси в коде. Трафик через VPN/сеть на уровне ОС. |
| **`proxy`** | Через HTTP-прокси из `OPENAI_PROXY` (или `HTTPS_PROXY`). |
| **`auto`** | `proxy`, если задан `OPENAI_PROXY`; иначе `direct`. |

Альтернатива: `OPENAI_USE_PROXY=true` / `false`.

В режиме **`direct`** приложение **игнорирует** `OPENAI_PROXY` и системные `HTTP_PROXY`.

### Примеры `.env`

**VPN (без прокси в приложении):**
```env
OPENAI_API_KEY=sk-...
OPENAI_CONNECTION_MODE=direct
LLM_MODEL=gpt-4o-mini
```

**Через прокси:**
```env
OPENAI_API_KEY=sk-...
OPENAI_CONNECTION_MODE=proxy
OPENAI_PROXY=http://логин:пароль@хост:порт
LLM_MODEL=gpt-4o-mini
```

### При старте

В выводе ноутбука:
- `🌐 OpenAI: прямое подключение (без прокси в приложении; VPN/сеть на уровне ОС)`
- или `🌐 OpenAI: через прокси (host:port)`

Если `OPENAI_CONNECTION_MODE=proxy`, но URL прокси не задан — старт с понятной ошибкой.

### Изменённые файлы

- `config.py` — `get_openai_connection_mode()`, `get_openai_proxy_url()`, `describe_openai_connection()`
- `content_utils.py` — клиент OpenAI с учётом режима
- `run_teachai.py` — вывод режима при старте, `config` в порядке reload
- `interface_utils.py` — сообщения об ошибках
- `setup_interface.py` — форма знакомства, переход к уроку, обработка ошибок API
- `course_plan_generator.py` — повторные попытки запроса
