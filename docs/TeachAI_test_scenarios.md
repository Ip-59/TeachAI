## Нужно твоё решение

| № | Вопрос | Моя рекомендация | Почему |
|---|---|---|---|
| D1 | Когда урок считается **завершённым** и что видит дашборд? | Завершён = (тест > 40 % **или** подтверждённый обход теста) **и** верное КЗ; либо явное «Продолжить с текущей оценкой». Открытый урок — «посещён», отдельный список; дашборд и время — только по завершённым | Сейчас три разных числа прогресса; так совпадёт с `is_lesson_completed` и отчётом этапа 2 |
| D2 | Засчитывать понятия, если ученик просто открыл список «Ключевые понятия»? | **Нет.** Засчитывать только после теста > 40 % или принудительного перехода; открытие списка — «просмотрено» | Открыть список ≠ усвоить; иначе КЗ будут опираться на непройденное |
| D3 | «Продолжить с текущей оценкой» после проваленного теста закрывает урок? | **Да**, но с пометкой `forced` в прогрессе и на дашборде | Это осознанный выбор ученика и прежнее поведение; пометка честно отделит его от сдачи |
| D4 | Можно ли показывать эталонное решение? | Только после верной сдачи или после 3 неверных попыток, по отдельной кнопке «Показать решение»; после показа урок не засчитывается этой сдачей | Сейчас эталон виден после первой ошибки и копируется |
| D5 | Неверная пересдача после верной — что хранить? | Хранить лучший результат и историю попыток | Урок уже закрыт; затирание делает статистику КЗ противоречивой |
| D6 | «Задание не требуется» после **обхода** теста — урок закрыт? | **Нет**: при обходе предложить тест; без кода урок закрывается только тестом > 40 % или явным «Продолжить с текущей оценкой» | Иначе урок закрывается без какой-либо проверки, вопреки отчёту этапа 2 |
| D7 | Курс вне области после «Всё равно начать» | Разрешить, но пометить «вне области» в «Моих курсах» и в промптах | Решение 20.10 — предупреждение + принудительный старт; пометка поможет отчётности |
| D8 | Нерелевантный вопрос учитывать в счётчике вопросов урока? | **Нет**, только вопросы, на которые дан ответ | Счётчик влияет на статистику ученика |
| D9 | Таймаут для кода ученика | 10 с, выполнение в отдельном процессе с CWD во временной папке и без переменных окружения с ключами | Закрывает KZ-16 и SEC-01/02 одним механизмом |

## Предложение по тестовой инфраструктуре

**Структура:**
```
tests/
  conftest.py            # фикстуры: tmp state (tmp_path + chdir), fake LLM, ipywidgets helpers
  fixtures/llm/          # записанные ответы: plan_*.json, lesson_*.md, assessment_*.json,
                         # examples_*.json, task_*.json, judge_*.json, domain_*.json, broken_*.txt
  unit/                  # М: state, progress, portfolio, outline policy, parsers, config, llm_route
  scenario/              # С: driver ноутбука + клики виджетов
  live/                  # Ж: помечены @pytest.mark.live, нужен OPENAI_API_KEY
```
- Перенести существующие `*_checks.py` в `tests/unit/` и убрать `tests/` из `.gitignore`.
- **Fake LLM:** подменять `content_utils.create_openai_client` (одна точка для всех генераторов) на клиент, который выбирает записанный ответ по типу запроса и пишет журнал вызовов. Так проверяется и число вызовов (кэш = 0). Запись ответов: режим `--record` один раз гоняет живую модель и сохраняет ответы в `fixtures/llm/`.
- **Driver ноутбука:** `nbclient`/`jupyter_client` запускает ячейку `TeachAI.ipynb` в настоящем ядре во временной копии `data/`; хелперы `click("Начать курс")`, `set_value(...)`, `screen_text()` по `Widget.widgets` (так был сделан прогон 25.10).
- **Запуск:** `pytest tests/unit` (секунды), `pytest tests/scenario` (~1 мин), `pytest -m live tests/live` (вручную, ≈30–40 вызовов gpt-4o-mini, около $0.01).
- **Когда что гонять:**
  - на каждый коммит (pre-commit или GitHub Actions): `unit` + быстрые `scenario` с fake LLM;
  - перед сдачей и после изменения промптов: `live` вручную;
  - раз в неделю: перезапись фикстур, чтобы ловить изменения формата ответов модели.
