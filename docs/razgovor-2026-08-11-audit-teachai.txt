ОТВЕТ 1 (ассистент) — первый аудит
--------------------------------------------------------------------------------

Ключевые проблемы (по критичности)

### Critical

1) Небезопасное выполнение произвольного кода (exec)
   Где: control_tasks_interface.py, control_tasks_generator.py,
        interactive_cell_logic.py, cell_widget_base.py
   Проблема: пользовательский и/или LLM-код выполняется в текущем процессе
   без изоляции. Открывает путь к вредоносным командам, чтению файлов,
   зависаниям.
   Исправление: sandbox (отдельный процесс/контейнер), ограничение builtins,
   запрет импорта/IO/сети, timeout + принудительное завершение процесса.

2) Выполнение кода, сгенерированного LLM (solution_code)
   Где: control_tasks_generator.py
   Проблема: код от модели исполняется как доверенный (риск prompt injection).
   Исправление: не исполнять solution_code в основном процессе; валидировать
   AST + sandbox, либо проверять решение без exec.

### High

3) HTML-инъекции в Jupyter UI
   Где: control_tasks_interface.py
   Проблема: description, error_message, solution_code вставляются в
   widgets.HTML как raw HTML.
   Исправление: html.escape всех динамических строк; код в безопасном pre.

4) Обязательный proxy не согласован с документацией
   Где: config.py, README.md, llm.py / content_utils.py
   Проблема: в коде запуск падает без proxy, в README это не отражено.
   Исправление: сделать proxy опциональным ИЛИ явно описать во всех сценариях.

5) Утечка чувствительных данных через debug-вывод
   Где: control_tasks_interface.py, control_tasks_generator.py
   Проблема: логируются промпты, фрагменты пользовательского кода, ответы модели.
   Исправление: централизованный logger, уровни, маскирование, флаг DEBUG.

6) Нет ограничений времени/ресурсов для проверки кода
   Где: control_tasks_interface.py, control_tasks_generator.py
   Проблема: бесконечные циклы блокируют интерфейс и сессию.
   Исправление: timeout, лимиты CPU/RAM, отдельный процесс.

### Medium

7) Дублирование фасада интерфейса
   Где: interface.py и interface_facade.py
   Проблема: оба содержат class UserInterface, риск расхождения логики.
   Исправление: один источник истины, второй — thin-wrapper или удалить.

8) Несколько версий одного форматтера
   Где: content_formatter.py, content_formatter_v2.py, content_formatter_final.py
   Проблема: путает импорт и поддержку.
   Исправление: выбрать canonical-версию, остальные убрать/архивировать.

9) Чрезмерно широкие except Exception и silent-fallback
   Где: control_tasks_generator.py, engine.py и др.
   Проблема: реальные ошибки скрываются под «успешными» fallback.
   Исправление: ловить точечные исключения, критические — пробрасывать.

10) Хрупкий парсинг JSON-ответов модели
    Где: control_tasks_generator.py
    Проблема: вырезание по find("{")/rfind("}") даже при json_object.
    Исправление: строгая схема (pydantic/jsonschema), прямой parse.

11) Использование eval при проверке выражений
    Где: cell_widget_base.py, control_tasks_generator.py
    Проблема: лишний риск и нестабильность.
    Исправление: ast.literal_eval для литералов; остальное — sandbox.

12) Hardcoded тема курса
    Где: llm.py
    Проблема: в generate_course зашита строка
    "Искусственный интеллект и машинное обучение".
    Исправление: брать тему из config, добавить тест.

### Low

13) Слабая поддерживаемость .gitignore
    Где: .gitignore — глобальное *.json (исключение только courses.json).
    Исправление: таргетированные пути (data/*.json, logs/*.json).

14) Документация частично расходится с реальным поведением
    Где: README.md, install_dependencies.py
    Исправление: синхронизировать шаги запуска, env, entrypoints.

15) Тестов фактически нет
    Где: отсутствуют test_*.py / *_test.py
    Исправление: smoke/integration для state_manager, engine,
    control_tasks_generator, безопасное исполнение кода.

Практичный порядок устранения:
- Итерация 1 (безопасность): sandbox + отключение raw HTML + timeout/limits.
- Итерация 2 (надежность): убрать дубли, сузить except, нормализовать JSON.
- Итерация 3 (поддержка): README/конфиг, зачистить debug-print, базовые тесты.

Что уже улучшилось (после правок)

По сравнению с предыдущим состоянием проекта заметны существенные улучшения:

- Убраны дубликаты: interface_facade.py, старые content_formatter*.py, llm.py,
  install_dependencies.py и др.
- В README явно указан обязательный OPENAI_PROXY.
- Контрольные задания: LLM-проверка (validate_solution_with_llm), модуль
  result_checker.py, стабилизация sklearn, resolve_executable_code,
  расширенные инструкции для студента.
- Экранирование HTML в инструкциях заданий и в примерах (html.escape в
  control_tasks_interface.py, examples_html_utils.py).
- Рендеринг уроков: content_renderer.py (таблицы, LaTeX → MathML).
- При ошибке парсинга задания fallback теперь с is_needed: false, а не
  «ломаный» generic-task.

Актуальные проблемы, которые всё ещё стоит закрыть:

### Critical — безопасность выполнения кода

1) exec() без изоляции и таймаута
   Где: control_tasks_interface.py, control_tasks_generator.execute_code(),
        examples_display.py, examples_validation.py, interactive_cell_logic.py,
        cell_widget_base.py.
   Проблема: код студента и эталонное solution_code выполняются в процессе
   Jupyter с полными правами. Возможны зависания (while True), чтение файлов,
   сетевые вызовы.
   Исправление:
   - Вынести выполнение в subprocess с timeout (например, 5–10 с).
   - Ограничить builtins (без open, __import__, eval).
   - Для TeachAI в ноутбуке — минимум: общий safe_execute(code, timeout=...),
     использовать везде вместо прямого exec.

2) Выполнение кода от LLM как доверенного
   Где: control_tasks_generator.validate_task_execution() — эталонное решение
   снова прогоняется через exec.
   Исправление: не исполнять solution_code в основном процессе; сравнивать
   через sandbox или только LLM + снимок переменных без повторного exec
   в том же namespace.

### High — устойчивость и безопасность UI

3) Частичное экранирование HTML (XSS в Jupyter)
   Исправлено: инструкции задания (_format_task_instructions).
   Всё ещё без escape:
   - заголовок задания (title из LLM);
   - подсказки hints (control_tasks_interface.py);
   - вывод output и str(e) в <pre> / <p>;
   - эталонное решение в <pre>;
   - контент уроков через enhance_content() / render_markdown_to_html() —
     HTML от модели попадает в widgets.HTML как есть (lesson_display.py,
     lesson_interaction.py);
   - lesson_title в тестах (assessment_interface.py).
   Исправление: единая функция safe_html(text) / safe_pre(code); для
   LLM-контента — bleach с whitelist-тегов или рендер только через markdown
   без сырого HTML.

4) Отладочный шум в production-потоке
   Где: control_tasks_interface.py — ~14 блоков [DIAGNOSTIC] с print, в т.ч.
   фрагменты user_code.
   Исправление: заменить на logger.debug(...) под флагом TEACHAI_DEBUG=1;
   в ноутбуке не печатать пользовательский код.

5) Нет автотестов
   В репозитории по-прежнему нет tests/ и test_*.py, при этом .gitignore
   исключает папку tests/.
   Исправление: минимальный набор:
   - test_resolve_executable_code, test_values_equal;
   - парсинг JSON заданий;
   - порог прохождения теста;
   - smoke ConfigManager (с mock API).

6) Тяжёлые зависимости «на всех»
   Где: requirements.txt — tensorflow, flask, yfinance и т.д. для опциональных
   курсов.
   Исправление: разбить на requirements-core.txt + requirements-ml.txt /
   extras в pyproject.toml; в README — установка по выбранному курсу.

### Medium — логика и архитектура

7) Порог «тест пройден» захардкожен
   Где: learning_progress_manager.py, assessment_results_handler.py —
   везде > 40.
   Исправление: константа PASS_THRESHOLD_PERCENT = 40 в config.py или
   .env (TEST_PASS_THRESHOLD=40).

8) Обход проверки задания
   Где: кнопка «Продолжить с текущим результатом» →
   mark_lesson_complete_manually().
   Проблема: урок может считаться завершённым без успешного контрольного
   задания.
   Исправление: явно различать статусы completed / skipped / failed;
   не считать skipped как 100% прогресс в дашборде.

9) Хрупкий парсинг JSON
   Где: control_tasks_generator._parse_control_task_response() — вырезание
   {...} через find/rfind, хотя API уже с response_format=json_object.
   Исправление: json.loads(response) напрямую + pydantic-модель полей задания.

10) eval в интерактивных ячейках
    Где: cell_widget_base.py (последняя строка выражения).
    Исправление: только ast.literal_eval для литералов; иначе не вычислять
    автоматически.

11) Контент урока: XSS + неконсистентный pipeline
    lesson_display.py: то render_markdown_to_html, то «уже HTML как есть»,
    потом enhance_content без санитизации.
    Исправление: один pipeline: markdown → HTML → sanitize → widget;
    не пропускать сырой HTML от LLM без фильтра.

12) Широкие except Exception и тихие fallback’и
    Где: генераторы, engine.py, прогресс.
    Проблема: скрывают реальные сбои (API, JSON, файловая система).
    Исправление: ловить узкие исключения; критические — пробрасывать с
    понятным сообщением в UI.

### Low — поддержка и DX

| Проблема | Где | Исправление |
|----------|-----|-------------|
| .gitignore игнорирует *.json и tests/ | .gitignore | Точечные пути: data/*.json, не блокировать тесты |
| Нет .env.sample в репозитории (только создаётся runtime) | config.py / README | Закоммитить .env.sample (без секретов) |
| Pre-commit только Black | .pre-commit-config.yaml | Добавить ruff, mypy (хотя бы на ключевые модули) |
| Мало type hints (правило проекта) | многие модули | Постепенно для публичных API |
| Placeholder лицензии/автора | README.md | Заполнить или убрать секции |
| engine.py — много print вместо logger | engine.py | logger.error + один виджет ошибки в UI |
